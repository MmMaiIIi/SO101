# Real deployment bugs and fixes

| Symptom | Root cause | Evidence | Fix | Regression protection | Remaining limitation |
|---|---|---|---|---|---|
| One missing Feetech `Present_Position` status packet killed a run | A transient `sync_read` failure was fatal after one attempt | Feetech log reported no status packet after one try | Backported LeRobot PR #4207 behavior: `num_retry=2` (up to 3 attempts); control worker owns the serial bus; failed tick sends no new target; stop only when state freshness expires | Bounded retry and single-owner code/tests; latest successful run had 1,320 read calls and 0 extra attempts | Persistent bus/device failure still stops execution |
| Small elbow inward recovery stalled | P/I/D was 16/0/32 and small commands fell within the servo dead-band/static friction | P=16: raw 3095→3093 then stalled; P=32: 3093→3086 in about 0.74 s | Temporary P=32 only during bounded inward startup recovery; restore normal P=16 and keep torque enabled | Recovery logs verify inward progress, register/temperature/current/status, and gain restoration | Applies only to the observed startup recovery case |
| Slight measured-state drift outside saved calibration prevented recovery | Measured-state bounds and command-target bounds were treated identically | Live elbow briefly exceeded the saved envelope while the desired recovery target was interior | Separate measured-state drift from command bounds; permit only strictly inward recovery for a small supported drift; an out-of-range Goal remains a hard rejection | Recovery targets are asserted strictly inside saved bounds; calibration limits are unchanged | Calibration endpoints are not an independent certification of mechanical collision limits |
| Dataset percentile slew triggered as if it were a mechanical hard limit | Distribution-derived command delta/velocity caps were conflated with physical limits | Recorded legitimate GT transitions exceed percentile caps; policy slew warnings also occurred | Absolute/calibration position bounds, NaN/Inf, stale state/camera, and communication remain hard stops; percentile slew is warning/diagnostic only | Safety tests retain hard position rejection; no clipping or hidden interpolation | Model commands can still be rejected at absolute bounds |
| Immediate tracking-error abort after a target write | State was compared with a just-written target before the servo had time to respond | First commands had large instantaneous errors while the arm began moving | Evaluate direction, progress, and persistence over a bounded response window; stop on sustained non-progress or divergence | Live control logs track progress and persistent error | Physical tracking behavior remains robot-, pose-, and load-dependent |
| WAN inference request took about 3 s | Raw RGB transport designed for localhost was used over WAN | Raw payload was about 1.84 MB; server body receive took about 2.3 s | Use lossless PNG for front and wrist over a persistent connection; do not resize at transport; saved processor alone performs image preprocessing | PNG verification: decoded pixel diff 0; state/processed tensors diff 0; same-seed 50×6 action diff 0 | WAN remains variable and slower than local inference |
| Concern that PNG transport altered policy inputs | Encoding/decoding or preprocessing might have changed image/tensor values | Saved equivalence report compares direct and PNG routes | Verified exact pixels, state, processor inputs, and fixed-seed output chunk | `png_equivalence.json` evidence is local; compact result is summarized here | Re-run if protocol or image code changes |
| Only 10 model actions were executed per prediction | Historical synchronous `n_action_steps=10` was mistaken for a model/output limit | Native async `predict_action_chunk` returns 50×6 actions | Async deployment consumes up to 50 steps; control is 30 Hz; nominal horizon 1.667 s | Queue tests enforce sequence/time alignment, chunk expiry, and no stale replay | Long-horizon behavior is a deployment choice, not a training guarantee |
| Queue could empty before inference returned | Next request was made too late and expired prefixes were not handled as a timed stream | WAN request latency overlaps multiple 30 Hz ticks | Refill at 0.6 remaining fraction; align by observation tick; discard expired prefixes; safe hold when empty; never replay stale chunks | Async queue tests and live `stale_replays=0` | Latest successful run had 130 underflow ticks, handled by safe hold |
| A network failure interrupted one attempt | SSH forwarding tunnel dropped during the request | Attempt log records timeout; following run used restored tunnel | Restore the persistent tunnel and start a fresh attempt; do not replay the timed-out request or old action chunk | Sequence checks and connection close on request exception | Tunnel health still depends on the rented server/network |
